The source-based interpretation is a **polycentric ecosystem**: research-led semiconductor and health ventures around Leuven; enterprise software and AI around Ghent; fintech, insurtech and cross-border services in Brussels; industrial and logistics links around Antwerp; and aerospace, industrial electronics and life sciences across Wallonia. This is an analytical synthesis of the cited hubs and reviewed companies, not a statistically weighted sector ranking.

## Provenance, access and data contracts

Each fact or unresolved observation carries its exact source URL, publisher classification, retrieval timestamp, publication/effective date where established, short evidence paraphrase, confidence, review status and rationale. Some tranches use a precisely labelled research-window completion receipt for `retrieved_at`; this is not represented as an exact per-request timestamp. Full source text is not archived. Failed reads remain in the registry and cannot support accepted claims.

The ledger uses the enrichment helper's existing source-kind vocabulary. Thirteen deeptech claims map university/programme `primary_institution` classification conservatively into its `secondary` compatibility bucket while retaining `source_kind_original` and the mapping explanation. The registry keeps the actual publisher classification. This is a compatibility mapping, not a new production schema.

`records.json` uses only the existing `validateStartupRecord` fields. Unsupported structured geography, date precision, transaction kind and investor participation remain in the sidecar or sourced profile facts/notes. Unknown fields are null with dispositions in research data and omitted in the production projection. Amounts are never set to zero to indicate missingness. Founding observations use independently sourced profile facts rather than inheriting an unrelated top-level source.
