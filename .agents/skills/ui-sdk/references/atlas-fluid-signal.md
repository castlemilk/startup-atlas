# Atlas Fluid motion companion

Use this project-specific companion when adding Fluid motion to Atlas UI SDK controls or the separately owned React/Hardware application. The installed upstream UI SDK skill and `skills-lock.json` remain unchanged. Read `docs/design/fluid-signal-adapter.md` for the API, exact package provenance, build and evidence contract.

1. Refresh main, open PRs and the canonical Design System Space. Identify the actual framework, versions, router and owner. Static Atlas and Hardware/Next.js are distinct surfaces; a static field guide is not an installed React component.
2. Preserve `web/design-tokens.css` as the theme authority. Read computed 140/240ms tokens at the root, including intentional zero and host overrides. Use scoped Fluid aliases; never import its global theme over Atlas. Historical handbook 220ms is not the canonical timing.
3. Use the exact reviewed `@usefluid/motion` package and its published APIs. Current web documentation can describe unpublished releases. Preserve release-age and install-script policies. A blocked dependency stays blocked; keep the native/static result.
4. Keep the host's committed state, UI SDK keyboard/focus/ARIA, native backing controls, URL/history and evidence labels authoritative. Motion consumes the result. Do not drive success, authorization, saving, focus return or route changes from an animation callback.
5. Reuse existing ownership. For the bounded adapter, use one `mountFluidSignal(root)` owner and exclusive descendant layers with canonical `transform: none`. Leave the GSAP pilot, globe, graph and handbook owners untouched. Do not add Fluid `play` or a second RAF loop to the same visual work.
6. Commit final layout first, then supply the previous-to-next **destination** delta in the same rendering turn. Do not supply the already-animated bounding rectangle. The adapter composes its interrupted offset; continuity is positional, not velocity-continuous physics. Use the host's own presence/exit mechanism for SDK popups.
7. Unsupported CSS `linear()` uses valid Signal easing. Stay static when no easing/animation is usable, duration is invalid/zero, motion preference is unknown/unobservable, reduction is requested or the document is hidden. Live reduction/visibility cancels owned effects; restoration does not replay. Call idempotent destroy before unmount; preserve sibling and foreign effects.
8. In React, mount after client commit and close cleanup over the exact instance. Render final content on the server. Test real hydration, Strict Mode, router/Suspense and SDK integration only with the identified owner's stack; a peer range or Node import does not prove them.
9. Run source/DOM lifecycle tests, reproducible bundle check and the applicable native acceptance. Separate doubles, synthetic visibility, actual browser rendering, physical-device checks and live release evidence. Check focus, narrow layout, reduced motion and Back/Forward in the consuming owner's specimen.
10. Keep owned paths additive until API/file agreement. Save exact revisions and gaps to the Space. Obtain independent review and coordinated approval before shared integration, merge or deployment. Existing illustrations remain concepts with their original provenance.
